## 5. Key findings the table cannot hold

- PBO appears five times. Three (ML, Screener, Portfolio) compute the same statistic. Research ledger and Research reports use different rules (`services/research_v2/core/ledger_math.py`, `services/research_v2/reports.py`). Pick one.
- Deflated Sharpe appears in four places with the same formula. The Portfolio default (`services/portfolio_v2/core/stats.py`, `deflated_sharpe_ratio`) uses estimator variance, not the cross-trial variance that Research uses (`services/research_v2/store/ledger.py:27`).
- Three purged-CV engines exist (row 11). Each uses a different purge unit. Results will not match until one is chosen.
- Three cost loops (row 10) solve the same equation. Merging them should reproduce NAV to floating-point tolerance. This is the safest early merge on the execution side.
- Covariance: Ledoit-Wolf and OAS are sklearn calls in four modules (`services/portfolio_v2/core/covariance.py`, `services/pca_v2/core/pca_math.py`, `services/volatility_v2/core/covariance.py`, `services/ml_v2/core/allocation.py`). The legacy constant-correlation LW is gone.
- Black-Litterman posterior matches between Portfolio and PCA. Only the default Omega differs.
- HRP: same algorithm, but ML uses ward linkage and Portfolio uses single linkage. The same universe gives different weights.
- Cornish-Fisher kurtosis bug: closed. `services/strategy_engine.py` was deleted.
- Job state is split inside Research: `services/studio/jobs.py` JSON store and `services/research_v2/store/db.py` SQLite table (`api/research_v2.py` writes both).
- Uploads: six implementations. ML's is the strongest (formula rejection, caps) and is the decided source.
- Frontend: the seven `customPagePrimitives.jsx` files were deleted with the old v2 frontends. `Exhibit`, `KpiStrip` and `charts/v2` still do not exist.
