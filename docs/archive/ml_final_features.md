## FEATURE 1 — Purged K-Fold and Combinatorial Purged Cross-Validation Engine (CPCV)

**The money:** This is the single feature that separates every serious quant research desk from every toy backtester in existence. Standard K-Fold cross-validation is provably wrong for financial time series. Financial returns are serially correlated: observations close in time share information. When you train on observations that temporally overlap with the test set, your model has already "seen" what it is predicting. The result is a backtest Sharpe ratio that is a fabrication. Purged K-Fold eliminates training observations whose label-formation windows overlap in calendar time with any test observation. The Embargo extends the gap beyond the purge window to absorb residual autocorrelation leakage. Combinatorial Purged CV (CPCV) goes further — first introduced in Lopez de Prado's _Advances in Financial Machine Learning_ and independently validated in Simões et al. (2024, _Knowledge-Based Systems_) who demonstrated across synthetic controlled environments that CPCV produces measurably fewer false strategy discoveries than all walk-forward variants. Instead of a single walk-forward path, CPCV generates every combinatorially possible backtest path through the data, producing a full distribution of Sharpe ratios rather than a single lucky number. The gap between the CPCV Sharpe distribution and the naive K-Fold Sharpe is the precise quantification of how much a strategy is data-mined. QuantConnect does not have this. Portfolio Visualizer does not have this. CPCV is in Lopez de Prado's textbook, cited in hundreds of quant papers, and absent from every platform a researcher can buy.

**What it computes:** For Purged K-Fold: partition T observations into K folds. For each test fold, identify all training observations whose label-formation window overlaps in calendar time with any test observation. Purge those observations. Apply an embargo of E additional observations after each test fold. For CPCV: choose N groups and k test groups. Generate all C(N,k) possible splits. Fit the model on each training complement, predict on each test group. Combine test-period predictions across all splits into multiple non-overlapping backtest paths. Report the full distribution of out-of-sample performance metrics. Compute the Deflated Sharpe Ratio (DSR) — Bailey et al. — which corrects the CPCV Sharpe for multiple testing bias across all configurations tested in the research session.

## FEATURE 2 — Gradient-Boosted Tree Alpha Engine with Full SHAP Attribution

**The money:** Gradient boosting is the single most widely deployed ML architecture for cross-sectional equity return prediction at quant funds. Gu, Kelly, and Xiu (2020, _Review of Financial Studies_) showed on a 30,000-stock US equity universe spanning 1962–2016 that gradient-boosted trees — alongside deep neural networks — consistently outperform all linear factor models in OOS return prediction, with the largest predictive gains in the tails of the return distribution exactly where portfolio returns matter most. AQR, Schroders, and Man Numeric all run variants of gradient-boosted cross-sectional prediction internally. The critical gap in every retail platform is explainability: without SHAP (SHapley Additive Explanations), the answer to "why does the model like this stock" is "the model said so" — which is institutionally untenable and, in 2026, legally problematic under emerging AI disclosure frameworks. Tree-SHAP computes exact Shapley values for every tree-based prediction, attributing each output to each input feature with mathematical rigor derived from cooperative game theory. The IC-weighted ensemble dynamically reweights each model family daily on recent predictive accuracy — no commercial platform exposes this to a user.

**What it computes:** Fit XGBoost, LightGBM, and CatBoost on the cross-section of price-based stock features at each rebalancing date, validated under CPCV from Feature 1. Generate next-period return predictions. Compute SHAP values for every prediction via TreeExplainer (exact, polynomial-time for trees). Compute rolling Spearman IC per model per asset. Ensemble via IC-weighted averaging updated at each rebalancing date. Generate IC decay profile showing how far forward the signal remains informative.

## FEATURE 3 — Multi-Horizon Volatility Forecasting Engine: GINN + HAR-ML Ensemble

**The money:** Volatility forecasting is the input to every downstream risk metric — VaR, CVaR, margin, position sizing, stress testing. The academic record through 2025 is definitive across three converging research lines. First: Christensen, Siggaard, and Veliyev (2022, _Journal of Financial Econometrics_) showed ML algorithms — including Random Forests and regularized regressions — beat the HAR lineage across all horizons from 1-day to 22-day on Dow Jones Industrial Average constituents, even with minimal hyperparameter tuning. Second: Xu, Liechty, Benthall, Skar-Gislinge, and McComb (ACM ICAIF 2024) demonstrated that the GARCH-Informed Neural Network (GINN) — an LSTM whose loss function is augmented with a GARCH-consistency penalty, forcing the neural network to satisfy the GARCH variance recurrence while using its full capacity for nonlinear patterns — achieved superior OOS R², MSE, and MAE versus both standalone GARCH and standalone LSTM on US equity volatility data. Third: multiple studies through 2025 including the HAR-LSTM-GARCH hybrid (January 2026, _Journal of Risk and Financial Management_) confirm that combining econometric structure with neural network flexibility in a single architecture systematically outperforms either class alone. No retail or institutional subscription platform runs all four model families in parallel with IC-weighted ensembling and multi-horizon output. Portfolio Visualizer shows historical vol and nothing else.

**What it computes:** Four model families in parallel, IC-weighted ensembled. Model 1: HAR — realized vol as a linear combination of daily, weekly, and monthly realized variance lags (Corsi 2009), the benchmark model in the vol forecasting literature. Model 2: GARCH family — GARCH(1,1), EGARCH, GJR-GARCH, TGARCH — each fit by MLE with AIC model selection. Model 3: GINN — LSTM with GARCH-consistency loss penalty (λ-weighted), forcing the network to satisfy the GARCH recurrence while using LSTM capacity for nonlinear residual patterns. Model 4: HAR-ML — HAR extended with cross-asset spillover features (VIX from FRED, yield curve slope from FRED, realized vol of user-selected tickers) selected via ElasticNet or LightGBM. Ensemble: IC-weighted combination of all four at each horizon, updated daily on rolling 63-day QLIKE accuracy.

**Realized vol proxy:** With daily OHLCV data and no intraday data, the platform uses the Garman-Klass estimator (most efficient daily proxy) and Yang-Zhang (handles overnight gaps). Both displayed and user-selectable. This is honest about the data available and still produces legitimate vol forecasts — Christensen et al. (2022) used these exact daily estimators.

## FEATURE 4 — Meta-Labeling and Triple-Barrier Label Engine

**The money:** This feature is entirely derived from Lopez de Prado's _Advances in Financial Machine Learning_, Chapters 3 and 10, and it is the most important idea in applied quant ML that no platform has implemented interactively. Fixed-horizon labels — stock return over next N days — are path-independent. They ignore whether a position would have been stopped out before N days elapsed. A trade that returns +3% at day 21 but drew down −8% at day 7 is labeled a winner by every naive backtester ever built. That labeling is a lie that trains any downstream model on falsified data. Triple-Barrier Labels fix this by defining a label based on which barrier is hit first: the profit-taking barrier (upper), the stop-loss barrier (lower), or the vertical barrier (maximum holding period). Meta-Labeling separates the direction and sizing problems: a secondary model trained on the primary model's signals predicts whether the primary model will be correct. The meta-model's probability output becomes the position sizing signal. The result is a model that knows not just where to go but when to size up versus when to cut exposure — precisely the distinction between a raw signal and a tradable strategy.

**What it computes:** For each event, define three barriers in price space. Simulate the price path forward and record which barrier is hit first. Label: +1 (upper hit), −1 (lower hit), 0 (vertical hit, timed out). For meta-labeling: train a primary model. Record all signals. Train a secondary (meta) model with label = 1 where the primary model was profitable on that trade, 0 otherwise. Meta-model output = predicted probability the primary model is correct on the current signal. Multiply primary direction by meta-model probability to produce a continuous position size.

## FEATURE 5 — Hierarchical Risk Parity Portfolio Optimizer with RL-Enhanced Rebalancing

**The money:** Lopez de Prado introduced HRP in 2016 at Guggenheim Partners (_Journal of Portfolio Management_). It is now one of the most cited portfolio optimization papers in quantitative finance. The economic rationale is concrete: Markowitz mean-variance optimization requires inverting the covariance matrix, which is catastrophically unstable when N is large and assets are correlated. HRP bypasses matrix inversion entirely — it uses hierarchical clustering to group similar assets and allocates risk recursively via bisection, never inverting anything. Multiple OOS studies including Platanakis and Urquhart (2019) and the NUAM market study (2025) confirm HRP's OOS Sharpe advantage over Markowitz in volatile regimes when the covariance matrix is most ill-conditioned. The 2025 RL-BHRP paper (Kang and Tian, University of Toronto and McGill, August 2025) combined Bayesian HRP with a PPO reinforcement learning agent that learns optimal rebalancing timing across sector-grouped sub-portfolios — achieving approximately 120% cumulative return versus 101% for static HRP over the 2020–2025 OOS window on US equities. The Nested Clustered Optimization (NCO, Lopez de Prado) further improves on standard HRP by first optimizing within clusters, then between clusters using OOS estimates of within-cluster allocations, eliminating the data leakage that standard HRP incurs at the inter-cluster optimization step.

**What it computes:** Step 1: Estimate the N×N asset covariance matrix using any of five estimators. Step 2: Compute the distance matrix D where d(i,j) = √(0.5 × (1 − ρ(i,j))). Step 3: Hierarchical clustering. Step 4: Quasi-diagonalize the reordered covariance matrix. Step 5: Recursive bisection — allocate risk inversely proportional to intra-cluster variance from tree top to bottom. Optional NCO: optimize within each cluster independently, then optimize across cluster return series using OOS estimates. Optional RL rebalancing: a PPO agent determines when to rebalance based on detected shifts in the estimated correlation structure.

## FEATURE 6 — Market Regime Detection and Adaptive Strategy Routing Engine

**The money:** Every alpha signal, volatility forecast, and portfolio allocation in this platform behaves differently depending on the market regime. A momentum strategy that returned 2.0 Sharpe in low-vol trending markets may destroy capital in high-vol mean-reverting markets. A stat arb book that thrives when PC1 explained variance is below 40% collapses when synchronized selling drives PC1 above 70%. Regime detection is the meta-layer that routes all other features. The academic record through 2025 is clear: Hidden Markov Models remain the dominant framework (Rabiner 1989, extended to finance in Hamilton 1989) but suffer a documented failure mode — they can only predict _continuations_ of already-changed regimes, not predict the _onset_ of a new regime before it is experienced. The 2025 ensemble-HMM framework (Gupta, Kapoor, Gupta, Natesan, _Data Science in Finance and Economics_, October 2025) addressed this directly: by combining tree-based ensemble classifiers (Random Forest, XGBoost) with HMM in a voting framework, the model detects regime shifts earlier and with lower false positive rates than pure HMM. The heteroskedastic network approach (PMC 2025) further augments HMM with ARMA-GARCH structure to capture nonlinear time series dynamics. Regime-conditional λ in Feature 7 (faster forgetting in high-vol regimes) and regime-conditional barrier distributions in Feature 4 both source their regime state from this feature — making it the central nervous system of the platform.

**What it computes:** Four parallel regime detection frameworks. Framework 1: Gaussian HMM (2-state and 3-state) fit on the ensemble realized vol series and returns jointly, using Baum-Welch estimation. Framework 2: Gaussian Mixture Model (GMM) on a multivariate feature space (rolling return, rolling vol, rolling skew, rolling kurtosis, VIX level from FRED, yield curve slope from FRED). Framework 3: Ensemble-HMM voting classifier — XGBoost and Random Forest trained on labeled historical regimes (bear, bull, high-vol) combined with HMM state probabilities in a majority-vote ensemble, addressing the HMM's regime-onset detection failure. Framework 4: PCA structural break detector — tracks PC1 explained variance as a regime indicator (PC1 > 60% = synchronized market, low diversification benefit; PC1 < 35% = dispersed market, stat arb favorable). All four frameworks output current regime probabilities at each date.

## FEATURE 7 — Bayesian Online Learning and Dynamic Model Averaging Engine

**The money:** Every ML model in finance degrades. The regime that made XGBoost dominant last quarter makes it mediocre this quarter. Dynamic Model Averaging (DMA), introduced by Koop and Korobilis (2009, _Journal of Business and Economic Statistics_) and deployed across hundreds of applications in _Quantitative Finance_, _Journal of Empirical Finance_, and _Review of Financial Studies_, solves this formally: at every time step, a Bayesian updating rule reweights each candidate model according to its recent predictive accuracy, and the model with degrading performance loses weight automatically before the PM notices it has stopped working. Online Bayesian Stacking (OBS) — Waxman, Llorente, Djurić, _Transactions on Machine Learning Research_ (TMLR 2026, published April 2026) — now supersedes DMA in every empirically tested context: in all experiments conducted including S&P 500 forecasting with GARCH model ensembles estimated via Sequential Monte Carlo, OBS significantly outperforms both static BMA and DMA, with negligible additional computational cost. The theoretical result: OBS is connected to the online portfolio selection problem via online convex optimization, giving it formal regret guarantees absent from DMA. In non-stationary environments — exactly what financial markets are — OBS outperforms any fixed weight vector asymptotically. The forgetting factor λ controls how fast old evidence is discounted in DMA. It is the most powerful user-tunable parameter in any live quant system and it is never exposed on any commercial platform. Regime-conditional λ (faster forgetting in high-vol regimes, from Feature 6 routing) is the state-of-the-art 2025 extension.

**What it computes:** Maintain a library of M candidate models. At each time step: each model generates a prediction; each model's posterior predictive performance given the realized outcome is computed; DMA weights are updated via Bayes' rule with forgetting factor λ that exponentially discounts past evidence. OBS: solve a constrained optimization at each step minimizing the expected log-predictive score of the combined prediction, updated sequentially. OBS weights are provably superior in M-open settings — where no single model in the library is correctly specified — which is the always-true condition in financial markets. Weights logged in real time for every model at every date.

## FEATURE 8 — Multi-Factor IC-Weighted Composite Signal Optimizer with Walk-Forward Shrinkage and Full Orthogonalization

**The money:** WorldQuant's internal alpha combination engine is the most valuable piece of software in quantitative equity investing that nobody outside the firm has seen. It takes hundreds of raw alpha signals, strips each of its exposure to every other signal using Gram-Schmidt orthogonalization, evaluates each residualized signal's standalone IC, and combines them with weights proportional to their risk-adjusted predictive power — the IC-IR. The result is a composite signal maximally diversified across genuinely independent information sources. Three converging 2024–2026 research streams make this feature what it is. First: Han, He, Rapach, and Zhou (2024, _Review of Finance_, Volume 28, Issue 6) published E-LASSO — a three-step Fama-MacBeth procedure using LASSO regularization, forecast combination, and forecast encompassing for cross-sectional return prediction — demonstrating statistically significant OOS gains over both naive IC-weighting and equal-weighting across 94 stock characteristics. Second: AlphaForge (Shi, Song, Zhang et al., AAAI 2025, originally KDD 2024) proposed a two-stage framework combining generative neural network alpha factor mining with a dynamic combination model that adjusts factor weights based on temporal performance — demonstrating consistent OOS improvements over static factor combination. Third: Borri, Chetverikov, Liu, and Tsyvinski (_Higher-Order Asset Pricing Factors via Forward Selection Fama-MacBeth Regression_, arXiv March 2025, revised March 2026; NBER Working Paper 33663 April 2025) proved that the higher-order terms and interactions of six common factors — the FF5 model plus momentum — are significantly priced in the cross-section of equity returns, with a 7-term higher-order model improving cross-sectional R² from 31.2% to 59% and subsuming the majority of the factor zoo. None of this — orthogonalization, walk-forward shrinkage, dynamic IC weights, higher-order interaction screening — is available on any subscribable platform.

**What it computes:** Step 1: Accept any number of raw alpha signals (Factor Library, Feature 2, Feature 3, Feature 6 regime probabilities, or user-uploaded). Step 2: Cross-sectional z-scoring and winsorization at ±3σ. Step 3: Sequential Gram-Schmidt orthogonalization ordered by IC-IR descending — for each factor, regress it on all previously accepted orthogonalized factors and retain the residual, which is the factor's unique information after stripping all overlap with higher-ranked signals. Step 4: IC and IC-IR computation under Purged K-Fold from Feature 1. Step 5: Walk-forward weight shrinkage via E-LASSO (Han et al. 2024). Step 6: Higher-order interaction screening via Forward Selection Fama-MacBeth (Borri et al. 2025/2026). Step 7: Dynamic weight update at each cross-section via AlphaForge temporal performance model.

## FEATURE 9 — ML-Enhanced Pairs and Statistical Arbitrage Engine

**The money:** Avellaneda and Lee (2010, _Quantitative Finance_) is the foundational architecture of systematic equity statistical arbitrage, the same framework that institutional desks have run for two decades. The problem with every naive pairs trading implementation is pair instability — pairs cointegrated historically frequently break out-of-sample as market structure changes. A comprehensive 2025 survey (Sun, University of Warsaw Working Paper No. 22/2025) systematically reviewed ML, DL, RL, and DRL approaches to pairs trading and confirmed that the critical advances are: ML-based pair stability classification, structural break detection as a risk management layer, and RL-based entry/exit threshold optimization. Specifically: supervised ML classifiers trained on stability features prevent the catastrophic blow-up of a pair that stops cointegrating mid-position; structural break detection (wavelet + CNN-LSTM, from Huang et al. 2020) identifies regime changes before they become losses; and RL-optimized thresholds — demonstrated in the CA-DRL framework (Sermpinis et al. 2020) and confirmed in the 2024 IJFE RL stat arb paper which minimized empirical mean-reversion time via RL — outperform every static threshold approach across diverse markets. The network diversification framework — limiting concentration in connected components of the pair-sharing graph — prevents a stat arb book from being a disguised sector bet, a failure mode documented in every naive pairs book.

**What it computes:** Step 1: Universe reduction via hierarchical clustering — test only within-cluster pairs, eliminating the O(N²) multiple testing problem. Step 2: Cointegration test battery — Engle-Granger ADF and Johansen trace. Pairs must pass both at user-set significance. Step 3: Ornstein-Uhlenbeck parameter estimation — κ (mean-reversion speed), σ (long-run vol), half-life. Step 4: ML pair stability classifier — feature vector per pair (half-life, κ, ADF statistic, rolling correlation stability, hedge ratio drift, Hurst exponent of spread). Train XGBoost / LightGBM on historical pairs labeled stable vs. unstable. Classifier probability = pair quality score. Step 5: RL-optimized entry/exit thresholds via PPO maximizing net-of-cost Sharpe per pair, restricted to pairs with at least 150 historical episodes for training data sufficiency. Step 6: Network-aware portfolio construction limiting concentration in any connected component of the pair-sharing graph.

## FEATURE 10 — Market Microstructure Signal Observatory

**The money:** Every feature in this platform from 1 through 9 treats price and return as the primary observation. But price is the _output_ of a microstructure process — it is the equilibrium that emerges from order flow, liquidity provision, information asymmetry, and market impact. The signals that proxy for these processes using only daily OHLCV are an entirely orthogonal signal class relative to momentum, volatility, and factor-based alpha. They are orthogonal in an economically meaningful sense: Amihud illiquidity predicts returns through a risk-compensation channel, not through momentum or reversal. Roll's implied spread predicts returns through a market frictions channel. The MAX factor predicts returns through lottery-demand and investor attention channels. None of these mechanisms are captured by any existing feature in the platform — which means they add genuine, non-redundant predictive information to the Feature 8 composite. The 2025 ScienceDirect paper (GR-Net, 992 US stocks over 5,000 trading days from 2005 to 2024) demonstrated that ML-based liquidity estimates from daily OHLCV systematically outperform every classical microstructure proxy on the Acharya-Pedersen liquidity risk factor. All signals in this feature are computed entirely from yfinance OHLCV plus Ken French factors. Zero additional data.

**What it computes:** Eight signal families from daily OHLCV, cross-sectionally z-scored and winsorized. Family 1: Amihud illiquidity — |daily return| / daily dollar volume, averaged over rolling 21/63-day windows. Family 2: High-Low Amihud — uses (High − Low) / Close as the price impact proxy instead of |return|, more efficient estimator. Family 3: Roll's Implied Spread — 2 × sqrt(max(0, −Cov(r*t, r*{t−1}))) over rolling 21-day window; negative serial covariance of returns is the signature of bid-ask bounce. Family 4: Corwin-Schultz spread — estimated from daily high-low ratios using the Corwin-Schultz (2012) formula, the most accurate daily spread proxy without tick data. Family 5: Volume signals — turnover rate, dollar volume momentum (63-day vs. 252-day dollar volume growth), volume surprise (residual of daily volume from a regression on lagged realized vol and lagged volume — the component of volume not explained by volatility). Family 6: MAX factor — maximum single-day return over past 21 days; strong negative predictor (high lottery demand → return reversal); Bali, Cakici, Whitelaw, Journal of Financial Economics 2011. Family 7: 52-week high proximity — price / 52-week high; George and Hwang, Journal of Finance 2004; one of the most robust momentum variants across international markets. Family 8: Higher moments — realized skewness (21/63-day rolling), realized kurtosis, idiosyncratic volatility (IVOL from FF3 daily residuals, rolling 21-day).

## FEATURE 11 — Causal Factor Discovery Engine (Double/Debiased ML)

**The money:** Every feature in this platform from 1 through 10 does _prediction_. Feature 11 does _causal inference_. This distinction is not academic. A factor that predicts returns because it proxies for a genuine, persistent risk premium will continue to work as market participants learn about it — because the premium compensates for real risk that cannot be arbitraged away. A factor that predicts returns because it is spuriously correlated with another variable in the current sample will fail the moment that correlation breaks. Standard IC, IC-IR, and even Gram-Schmidt orthogonalization cannot separate these two cases — they tell you that a factor predicts, not _why_ it predicts. Double/Debiased Machine Learning (DML, Chernozhukov, Chetverikov, Demirer, Duflo, Hansen, Newey, Robins, Econometrica 2018) separates them. DML uses cross-fitting to orthogonalize each factor's effect with respect to all other factors and confounders, producing an Average Partial Effect (APE) estimate that is approximately unbiased, √n-consistent, and has valid confidence intervals regardless of model complexity or regularization. Applied to financial markets: the APE of a factor is its genuine causal contribution to the return cross-section after removing everything that other factors can explain about it. A factor with high IC but zero APE is a proxy for something else — it is not independently priced. The 2025 NeurIPS CauScien workshop paper (Rao and Rojas, UCLA) applied this exact framework to financial markets and showed that DML reveals causal drivers that OLS-based models misrepresent or obscure entirely. No platform in existence — not QuantConnect, not Bloomberg, not any institutional risk system — exposes DML causal factor decomposition to a user. This is the feature that turns the platform from a prediction engine into a research instrument that can answer: "Is my alpha real, or is it noise dressed as signal?"

**What it computes:** For each factor f in the active library, at each cross-sectional date: Step 1 — Nuisance model 1: regress f on all other factors using LightGBM with cross-fitting (K folds); obtain residual ẽ_f = f − f_hat. Step 2 — Nuisance model 2: regress realized next-period return r on all other factors using LightGBM with cross-fitting; obtain residual ẽ_r = r − r_hat. Step 3 — APE estimation: regress ẽ_r on ẽ_f using OLS; the coefficient is the DML Average Partial Effect of factor f on returns. Step 4 — Inference: compute heteroskedasticity-robust standard errors; 95% confidence interval for the APE. Step 5 — Compare APE to OLS IC: the gap (IC − APE) is the confounding bias — how much of the factor's predictive power is borrowed from correlated factors rather than genuine. Step 6 — Classification: Causal (APE significant, gap small), Proxy (APE significant, gap large), Spurious (APE not significant). Repeat for all factors, rolling walk-forward.

## FEATURE 12 — Deep Sequence Alpha Engine

**The money:** Your platform's entire ML module predicts cross-sectional returns using GBT (no temporal memory), LSTM (limited context window, vanishing gradient on long sequences), and GINN (structure-constrained to GARCH). The architectures above solve the specific failure modes of each. PatchTST divides the OHLCV + factor history into patches and applies Transformer attention across them — it can use 504 days of history with the same computational cost that LSTM uses on 63 days, because attention is applied across patches rather than timesteps. The iTransformer inverts the dimension: instead of attending across time for all assets simultaneously, it attends across assets for one timestep — making it natively suited to cross-sectional return prediction where the relationship between stocks at a given moment is the signal. The TFT handles the input types that define financial prediction better than any other architecture: static features (sector, size bucket), time-varying known future inputs (days to earnings, month-end flag, VIX term structure), and observed historical sequences (OHLCV, factor scores). The 2025 research from Carnegie Mellon's Tepper School confirms TFT-ASRO outperforms LSTM, XGBoost, and Random Forest simultaneously on Sharpe ratio prediction.

**What it computes:** Three architectures run in parallel as ensemble members, fed into Feature 7 (OBS engine) alongside GBT and LSTM. Architecture 1 — PatchTST: segment each asset's OHLCV + factor time series into patches of length P, encode each patch independently with a linear layer, run Transformer encoder attention across patches — captures both local structure (within-patch) and long-range dependencies (across-patch) simultaneously. Architecture 2 — iTransformer: invert the input dimensions — treat each asset's full time history as a single token, apply attention across assets at each timestep — natively models cross-sectional co-movement structure as a first-class object rather than as a residual. Architecture 3 — TFT: multi-head attention with gating network for static covariate embedding (sector, size), LSTM encoder for historical sequence processing, self-attention decoder for multi-horizon output, and variable selection network that automatically identifies which inputs matter at each timestep. All three validated under CPCV from ML Feature 1. SHAP attribution via integrated gradients (exact TreeSHAP not available for Transformers — integrated gradients is the mathematically correct substitute). IC decay computed at all horizons. Results fed as three additional ensemble members into ML Feature 7.
